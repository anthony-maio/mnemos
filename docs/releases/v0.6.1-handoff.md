## Isolated package preview

The following commands are prepared instructions, not an additional validation
result. They use the recorded Windows Python 3.11 path and a new disposable
environment/database with mock cognition and simple embeddings. This preview
inspects configuration and dependencies. Transport/persistence evidence belongs
to the recorded checks above; real-provider quality and pilot use remain open.

Use a separate disposable PowerShell session. Update only `$patchWheel` if the
verified artifact has been copied to the isolated Windows environment. These
commands do not register or launch Claude Desktop.

```powershell
$patchWheel = 'D:/Development/mnemos/mnemos/.worktrees/mnemos-improvements/.venv/storage-final-docs-v1/dist/mnemos_memory-0.6.1-py3-none-any.whl'
$expectedHash = 'a3abff76729ea4cc0fa0e8fbba8a087d60e50b8fb5c2324e6222ff44e6ff4463'
if ((Get-FileHash -LiteralPath $patchWheel -Algorithm SHA256).Hash.ToLowerInvariant() -ne $expectedHash) {
    throw 'The patch wheel does not match the reviewed artifact.'
}
$reviewRoot = Join-Path $env:TEMP ('mnemos-061-review-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $reviewRoot -ErrorAction Stop | Out-Null
$reviewEnv = Join-Path $reviewRoot 'venv'
py -3.11 -I -m venv $reviewEnv
if ($LASTEXITCODE -ne 0) { throw 'Review environment creation failed.' }
$reviewPython = Join-Path $reviewEnv 'Scripts/python.exe'
& $reviewPython -I -m pip --isolated install --require-virtualenv ($patchWheel + '[mcp]')
if ($LASTEXITCODE -ne 0) { throw 'Patch installation failed.' }
$env:MNEMOS_CONFIG_PATH = Join-Path $reviewRoot 'mnemos.toml'
Set-Content -LiteralPath $env:MNEMOS_CONFIG_PATH -Value '# Disposable package preview' -Encoding ascii
$env:MNEMOS_LLM_PROVIDER = 'mock'
$env:MNEMOS_EMBEDDING_PROVIDER = 'simple'
$env:MNEMOS_STORE_TYPE = 'sqlite'
$env:MNEMOS_SQLITE_PATH = Join-Path $reviewRoot 'memory.sqlite'
Set-Location -LiteralPath $reviewRoot
$doctorOutput = & $reviewPython -I -m mnemos.cli doctor
if ($LASTEXITCODE -ne 0) { throw 'Doctor did not complete.' }
$doctorReport = ($doctorOutput -join [Environment]::NewLine) | ConvertFrom-Json -ErrorAction Stop
$doctorReport | ConvertTo-Json -Depth 10
if ($null -eq $doctorReport.summary -or $doctorReport.summary.fail -gt 0) {
    throw 'Inspect the failed doctor checks before proceeding.'
}
if ($doctorReport.store_type -ne 'sqlite' -or $doctorReport.llm_provider -ne 'mock' -or $doctorReport.embedding_provider -ne 'simple') {
    throw 'Doctor resolved a different configuration from the disposable preview.'
}
```

Expected mock/simple warnings remain in the JSON report. Doctor's zero exit
code alone does not establish healthy checks. Dependencies resolved by a future
installation can differ from the recorded environment. A doctor result from
this preview is its own observation, not a replacement for the frozen
installed/native evidence.

## Rollback and data handling

The preview leaves the existing interpreter, host configuration and memory
database untouched. Stop its processes and close its disposable shell to
return to the existing setup. Keep the review directory and logs for diagnosis;
no deletion or live-data restore is needed.

An eventual approved live rollout must record the current interpreter and
host config first, quiesce all database users, and take a consistent SQLite
backup before switching profiles. The graph repair adds no schema migration;
opening a store updates its content-only FTS trigger. Keep the original
database and any post-update writes. Restoring an older backup would discard
new memories and must not be an automatic rollback action. Restoring the prior
interpreter/profile also restores that version's known defects.

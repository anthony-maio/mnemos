# 0.6.1 patch candidate

Status: prepared for validation, not published.

This patch targets SQLite graph writes and MCP startup in the existing 0.6.x
package. Graph-neighbor replacement uses a savepoint so a statement-level insert
failure restores the old edges and a caller's pending transaction remains under
the caller's control. Source and target checks occur while holding the write
lock, preserving the concurrent-client missing-source fix.

After a graph replacement fails and its savepoint is successfully rolled back,
the candidate logs a structured storage-failure event with the operation and
exception type. It excludes memory contents, identifiers, database paths and
exception messages. Logging failures do not replace the original storage error.
This event does not cover failed savepoint creation or rollback/connection failures.

The MCP extras require SDK 1.x. SQLite updates no longer reindex unchanged
content when access metadata changes. The plugin wrapper resolves an explicit
Python command against PATH, addressing Windows launches that selected an
interpreter without the expected dependencies. Explicit paths remain supported;
the selected interpreter must already contain Mnemos and its MCP dependencies.

The merged implementation passed hosted Python 3.10, 3.11 and 3.12 suites with
325 tests each, lint, automated MCP checks and both legacy benchmark repetitions.
That evidence belongs to the merged implementation. Packaging and installed
validation for this version must be recorded separately before publication.

This patch does not include the separate functional-memory development branch
or activate optional capture hooks. It makes no new claim about supported-answer
precision, complete capture/recall latency or completion of the two-week pilot.
No database schema migration is required for the graph transaction repair.
The content-only FTS trigger is updated when an existing SQLite store opens.

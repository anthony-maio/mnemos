# Relational producer screen stopped at its deadline

The frozen relational producer configuration failed operational feasibility on its first development question. The request reached the 15-second deadline without a complete reply. The harness recorded unavailable at 15,043.07 ms, stopped without retrying, and left the other 67 questions explicitly unattempted. The configuration is closed without promotion or deadline extension.

No development answer completed. Selected-fact precision is undefined; no expected-fact retention or correct-abstention credit was earned. The original denominators remain 40 expected facts and 28 absent-answer questions across 68 known questions. These counts describe missing acceptance evidence, not an estimate of semantic accuracy from a completed cohort.

The unrelated warmup returned a schema-valid reply in 9,774.91 ms of provider-reported total duration, generating 369 tokens. This timing excludes the full retrieval path. The first development request was still generating after 495 tokens in the retained server log before cancellation. Neither observation supports the original 500 ms complete warm retrieval target. They do not establish a universal throughput bound or show how an asynchronous annotation architecture would perform.

An offline source-span check of the warmup found three invalid offsets: the relation quote covered `owne` rather than `owner`, the value offsets covered ` is ` rather than `Mira`, and the whole-fact offsets omitted the end of the quoted sentence. The warmup only checked transport and response schema, as specified; it was never credited as semantic success. The strict evaluator would reject these spans. The separate diagnostic is retained at `.venv/relational-support-warmup-span-audit-v1.json`. No prompt or model was rerun to repair it.

Execution used the frozen 68 requests and policy, the retained Qwen3 14B model, explicit raw framing, structured-output schema, 8,192 context tokens and 2,048 maximum output tokens. Native token IDs were rechecked against the completed tokenizer preflight before generation. There were exactly two completion requests: the unrelated warmup and one development attempt. The latter has a preserved start and unavailable observation but no complete provider reply. The process exited zero because the harness handled and recorded the stop condition; that exit does not make the experiment successful.

Cleanup verified model unload, parent/native process absence and closed ports. All runtime and prepared-input hashes remained unchanged. The audit rechecked those bindings, starts, observations, untouched labels and the complete attempted/unattempted partition. The result rules out this configuration as a ready synchronous support path. A next design must account for both generation cost and provenance-coordinate reliability; simply increasing the timeout does not meet the original latency requirement. Semantic quality, fresh acceptance and full retrieval timing remain unproven. Canonical package behavior, the optional explicit-memory pilot and publication state are unchanged.

# Git configuration dependency discovery

The inactive capture prototype now asks the selected Git executable for system/global configuration roots and repository/worktree configuration paths. It inspects each file with Git's own parser, disables include evaluation for that parse, and recursively records every include target. Inactive conditional targets are included conservatively, so later activation does not introduce an unobserved file. Missing files remain dependencies whose creation changes the observation.

Each observation includes path components, file content and the existing ownership/access metadata checks. Discovery checks observations again after parsing and after completing the closure. Limits are 64 distinct configuration files, bounded include depth, the existing 64 KiB configuration-file bound, a five-second timeout per Git command and bounded accepted command output. These are discovery limits, not a complete capture timeout or a performance claim.

Malformed configuration, cycles, excessive dependencies, incomplete command output and changing observations prevent a usable result. Runtime-injected configuration overrides are currently unsupported and require authoritative fallback. Multiline environment values and paths containing parent traversal also require fallback: lexical removal of `..` could hide an earlier symbolic-link traversal. Ordinary relative include paths are supported. The helper does not alter Git configuration or interpret policy values itself.

The first six-case run had four failures because a disabled system configuration scope returns empty output with exit code 1. The corrected command handling accepts that empty outcome while rejecting other failed discovery. The original JUnit is retained at `.venv/policy-dependencies-v1.xml`; the corrected six-case run is `.venv/policy-dependencies-v2.xml`. After adding ambiguity and mutation tests, all 35 selected dependency/probe/cache cases passed in 26.43 seconds, retained at `.venv/policy-dependencies-v3.xml`. Black and diff checks passed.

The nine dependency cases exercise real Git discovery/parsing with temporary repositories, missing roots, relative transitive includes, inactive conditional targets, malformed syntax, inactive cycles and runtime configuration overrides. Additional cases reject multiline/parent-traversal inputs and simulate a file mutation at a deterministic observation boundary. They do not prove an atomic snapshot across arbitrary external writers.

This is dependency discovery, not a complete reusable policy owner. The next step must bind the executable and environment, combine routing and dependency freshness, avoid reparsing unchanged files without omitting new dependencies, and connect the live probe with authoritative fallback. Registry authorization must remain live per request. Canonical delivery, installed packages, live configuration and memory databases were unchanged. No timing run occurred and the cache remains inactive.

# Dispatch inspection and inference-only parity

The installed runtime reports FlashAttention unavailable despite its enable flag being true. For the 4,096-token Qwen head layout, the Transformers mask helper removes an all-ones mask and its SDPA helper enables GQA. A metadata-only probe then selects MATH for native grouped heads and EFFICIENT for explicitly repeated heads. Neither attention nor model forward ran in that probe. cuDNN capability alone returned true even when the actual selector chose MATH, so a capability boolean is not a dispatch result.

This is consistent with the [PyTorch 2.10 SDPA formulation](https://docs.pytorch.org/docs/2.10/generated/torch.nn.functional.scaled_dot_product_attention.html), which expresses grouped attention using repeated K/V heads and documents backend restrictions. The local source and probe are authoritative for the installed runtime. The metadata evidence identifies a concrete implementation candidate; it does not prove how much of the old 876.17 ms came from that dispatch or predict a new runtime.

`portable_grouped_sdpa.py` implements the opt-in representation policy. It preserves head order, complete sequences, masks, causal behavior, scaling and dtype. It does not force a backend or modify the installed SDPA registration. Its optional observer receives the final, possibly expanded tensors used by the actual call. A Qwen prefill adapter reuses the original mask constructor and rejects decode/sliding-window use.

The initial CUDA FP16 backward comparison failed the declared 2e-3 absolute/relative tolerance in four actual-layout subcases. A retained reproduction records those failures under `.venv/portable-gqa-parity-v1`, alongside the exact failing implementation and tests. Forward outputs passed. The revised candidate does not relax tolerance: it preserves the native grouped operator for Q/K/V gradient-bearing calls and applies the representation optimization only when those gradients are not required. This does not establish training speed or memory feasibility.

Eight final unittest checks passed in the retained torch runtime. They cover CPU float64 and CUDA float16 outputs and native grouped Q/K/V gradients, the 16/8 head ratio with head dimension 128, nonuniform upstream gradients, causal and boolean/additive masks, absent or unrecognized private dispatch capability, native and repeated inference representations, final dispatch observation, and a tiny random Qwen model using both padded and unpadded inputs. The integration test asserts that the custom adapter actually ran and that the original SDPA registration stayed intact. Decode input and learned attention masks are rejected. CPU tolerance remains 1e-10; CUDA tolerance remains 2e-3. These tests do not validate the rejected repeated-head backward.

No retained checkpoint weights were loaded in this increment. Small attention operations and a tiny random Qwen forward are numerical checks, not a new capacity run or semantic evaluation. The original failure remains closed. The [prospective candidate plan](../../plans/2026-11-08-portable-gqa-v1.md) requires a separately frozen, unchanged-workload computational test before any performance claim.

Independent review found no blocking defect in the intended no-grad full-attention prefill path. It required clarifying that final gradient tests exercise native grouped execution, not the failed repeated-head backward. That reporting correction is applied. The review supports a new frozen retained-model numerical/capacity comparison, not a speed or quality conclusion.

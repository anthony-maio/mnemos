# Condition-query token cost

Native Qwen3:14b tokenization completed for all 16 authored condition questions and their 16 reference replies. Full framed prompts used 316-437 tokens, median 429.5. Standalone minified reference replies used 15-29 tokens, median 28. The reference replies are authored examples; there were no semantic generation calls or model accuracy results.

The isolated Ollama 0.40.9 instance loaded the retained Qwen model with an empty prompt and zero generated tokens. Prompts used add_special/parse_special true; literal reply bodies used both false. The wrapper bound the model blob, runtime binaries and DLLs, source files, exact inputs and owner records before execution, then checked those hashes again after cleanup. The model unloaded, both owned processes disappeared and both loopback ports closed. Server exit 1 came from the verified owned-process stop; the wrapper exited 0.

This format has a smaller authored reply than the previous readable experiment's measured 72-token median generated reply, but those are different quantities on different tasks. These counts do not establish latency, semantic accuracy or a causal improvement. At the earlier observed generation rate of roughly 41 tokens per second, 28 tokens alone would take roughly 680 ms. That is only a planning estimate, not a measured bound, and it excludes prompt processing, retrieval and other interpretation. A sequential Qwen stage remains a poor candidate for the original complete 500 ms requirement without separate evidence. A bounded semantic development probe could still test whether this representation handles missing circumstances; it must not be presented as acceptance or integrated into the fast path on token counts alone.

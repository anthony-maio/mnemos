# Live policy sampling boundary

The inactive cache prototype now accepts a live `policy_probe` callback. It samples policy before considering an entry and again before returning a cache hit or publishing the result of authoritative resolution. A changed, unavailable, invalid or unreadable probe result discards the entry and delegates to authoritative Git. Environment equality is checked after the final probe, including when a probe itself changes the environment. Passing both the legacy static generation and a live callback is rejected.

The static generation argument remains for existing experimental callers, but cannot detect external policy changes during a call. It is not sufficient to enable caching under ordinary mutable Git configuration. The callback is only a sampling boundary; it does not discover external files or independently prove that its returned generation covers all dependencies. Ordinary filesystem changes immediately after observation remain a race to consider in the eventual owner contract; these checks do not claim atomic snapshots across arbitrary external writers.

All 26 cache and policy-probe cases passed in 18.50 seconds, including twelve new probe cases. They cover stable reuse, policy changes before reuse and during authoritative lookup, change during hit validation, unavailable/invalid values, exceptions, mixed API misuse and environment changes during the last sample. Existing tests retain real repository/worktree, registry and Windows ACL checks. Probe races use deterministic callbacks rather than uncontrolled external mutation. JUnit is `.venv/policy-probe-v2.xml`; the preceding 24-case result is retained at `.venv/policy-probe-v1.xml`. Black and diff checks passed.

Source inspection confirms that the authoritative resolver removes five routing environment overrides, uses DEVNULL stdin and calls `git rev-parse --git-common-dir` with its remaining environment. Installed Git is 2.51.0.windows.1. Read-only `git var GIT_CONFIG_SYSTEM` and `git var GIT_CONFIG_GLOBAL` returned the local system path and two user configuration paths. No configuration contents were exposed or modified.

Git documents that these variables report configuration paths even when absent, while disabled paths are omitted. The owner must therefore track creation of missing root files as well as changes to existing ones. Includes can add relative or expanded paths, and conditional includes depend on routing, branch or remote information. Those dependencies still need a bounded, verified owner; this change does not supply one. See the official [git-var contract](https://git-scm.com/docs/git-var) and [configuration includes](https://git-scm.com/docs/git-config#_includes).

Next implement root and transitive-include discovery, executable/environment binding and conservative authoritative fallback for unsupported or incomplete observations. The cache remains isolated and inactive. Canonical delivery, installed packages, live profiles and memory databases are unchanged. No timing experiment ran and no latency benefit is claimed.

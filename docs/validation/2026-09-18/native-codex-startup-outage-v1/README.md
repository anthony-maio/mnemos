# Native Codex startup outage and replay recovery

The installed c25ed98 wheel captured a real Codex prompt and final answer while a disposable service could not start. Its malformed TOML configuration produced a recorded startup failure. Generated hooks and normal client autostart were unchanged. Across 882 descriptor samples (maximum gap 64.7473 ms), no descriptor appeared; the core SQLite tables matched their seeded state with zero Codex captures. The native outbox retained exactly the two messages, with their actual session, turn, profile, project, role, and stable event identities.

The original native runner failed its exact reply assertion: the model returned `outage willow-raven` without the requested period. That failure report and traceback are unchanged. A separate recovery helper verified the actual native messages and continued from the existing queue without rerunning the model. It did not turn the failed text assertion into a pass.

An explicitly started installed fixture service acknowledged both events, and a second replay acknowledged zero. After service restart, a duplicate outbox replayed the same two original events. Facts, episodic events, evidence, and jobs had identical row counts and complete-row hashes before and after duplicate replay. Independent read-only verification found exactly one stored event and one evidence row for each captured message, with the expected scope and source identity. The foreign-project control remained intact. Temporary credentials and the runtime descriptor were absent after cleanup.

This is native capture during startup failure plus explicit service-client recovery with deterministic fixture embeddings and disabled optional modules. It is not automatic recovery by a second native host, real-model extraction quality, a process-kill or concurrent-host test, or a complete host acceptance result. Descriptor sampling cannot rule out a sub-sample transient. The recovery service used supplied fixture providers; restoring valid TOML syntax is not proof that a configured real-provider daemon starts. Prior native hook deadline and real-model gates remain separately bound.

The original native run, queue snapshot, startup stderr, recovery report, and verification are retained. Full native sessions, credentials, and databases are not archived. Exact pinned helper dependencies already preserved in the adjacent repeat archive are listed in `helper-dependencies.json`.

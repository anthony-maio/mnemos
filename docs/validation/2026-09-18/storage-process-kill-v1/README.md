# Storage worker termination checkpoint

Seven new cases terminate the actual SQLite worker at selected capture and forget boundaries. Capture is interrupted after event insertion, immediately before commit, and immediately after commit. Forget is interrupted after suppression insertion, after source deletion, before commit, and after commit. A wrapper calls the real SQLite execute/commit methods before or after publishing a boundary marker; the parent validates the marker and worker lineage, terminates that interpreter, and waits for its launcher.

Each case reopens the database and checks integrity and foreign keys. Pre-commit termination preserves the previous hashes of 12 application tables. Post-commit capture retains its event/job pair; post-commit forget retains suppression and erases the target source. Recovery replays the durable outbox, completes maintenance, preserves an unrelated same-project fact and a foreign-project fact, then repeats replay and restarts without changing the final table hashes. Forget cases also check revision, evidence, graph, and vector cleanup. The outbox ends empty. The expanded focused run passed 24 cases.

Test source `76940d2` passes 1,067 tests with four skips in a clean snapshot. All seven new cases also pass against the previously verified `983920a` wheel outside the source tree. The runtime, agents, and build configuration Git objects are identical between those commits; installed package files match the wheel byte for byte before and after validation. The copied test hash and seven JUnit case identities match. The [existing package checkpoint](../capture-forget-package-checkpoint-v1/README.md) retains build, type, 390-case installed, and replay evidence, plus its unresolved intermittent bridge failure.

These are deterministic storage-worker and HTTP replay tests with fixed embeddings and optional modules disabled. They do not establish native host concurrency, GPU/provider recovery, all possible crash timings, real-model quality, or pilot acceptance. A kill during the commit instruction itself was not attempted. Production code, the frozen evaluation, live configuration, and live data were unchanged.

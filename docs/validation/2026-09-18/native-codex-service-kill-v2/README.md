# Native capture across forced service termination

The installed c25ed98 wheel handled a real Codex CLI 0.146.0 prompt while a disposable service was forcibly terminated after its SQLite capture transaction and before the HTTP response. A server-side response barrier made that boundary reproducible. The parent verified the actual service PID and command, held its Windows process handle, terminated it with exit code 73, and observed termination. The captured user event and its original job survived; both native messages remained queued because no acknowledgment reached the hook. The stale descriptor still named the dead service.

An explicitly restored fixture service acquired ownership and replaced that descriptor. A fresh native Codex session then drained the old outbox through unchanged generated hooks, without a direct replay call. Both native processes exited zero. Exactly four native messages remained under their original session, turn, project, profile, role, and source identities. Each had one job and one evidence link. The committed-before-kill event retained its original event and job IDs. Facts, events, evidence, and jobs had identical complete-row hashes after native recovery, maintenance, service close, restart, and final cleanup. The foreign-project control remained intact.

The first native session displayed a Stop hook timeout at the unchanged three-second deadline. The second displayed an MCP startup-interrupted warning for codex_apps and mnemos. These terminal observations do not invalidate persisted capture and automatic hook replay, but this is not a clean all-hooks or MCP-readiness result. No model-directed tool calls occurred. Service restoration was explicit, optional modules were disabled, and embeddings were deterministic fixtures. This does not establish configured real-provider daemon recovery, arbitrary crash timing, concurrent-host behavior, native forgetting across a crash, latency percentiles, or complete host acceptance. Ordinary post-kill autostart attempts were not separately inventoried.

The original v1 preflight failed before any native session because a Windows virtual-environment launcher PID differed from its service child PID. Its scripts and failure report remain unchanged. A separate cleanup record documents absence of that process and removal of its stale descriptor. V2 validates the actual child identity and targets its process handle. Full native sessions, databases, and credential-bearing descriptors are not archived; selected synthetic records and hashes are retained.

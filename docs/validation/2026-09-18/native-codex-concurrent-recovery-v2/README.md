# Concurrent native Codex recovery

Four native Codex CLI 0.146.0 turns used installed source a5a9101 and unchanged generated hooks. Two separate Codex homes first ran during malformed disposable service configuration. Their four messages remained in one shared outbox; the database retained only its two seeded controls. After explicit fixture-service restoration, two fresh processes started together and their native hooks replayed the queue automatically. The harness never called replay_outbox.

A test-only barrier in the service submit path overlapped two queued capture requests. Windows TCP ownership and process ancestry tied the requests to both recovery Codex processes, rather than counting two threads or one client's retry as two hosts. The provenance helper was tested against a known local socket before use. All four native processes exited zero. Eight distinct user/assistant messages from four sessions had exactly one event, job, and evidence link each. The outbox emptied and both seeded controls remained intact. After maintenance, complete-row hashes for facts, events, jobs, and evidence remained unchanged through close/restart and final cleanup.

This is one bounded concurrent hook-recovery observation. It uses lexical fixture vectors, disabled optional modules, unavailable cognition, explicit service restoration, and an instrumented overlap barrier. It does not establish natural scheduling frequency, default daemon recovery, real-provider readiness, complete capture, Desktop, Hermes, or operational-pilot acceptance. Recovery-a displayed an MCP startup interruption; PowerShell also displayed Import-Clixml diagnostics. The separate terminal-observations record labels these as PTY observations, not durable log verification. MCP startup acceptance remains open.

The failed v1 fixture is retained. Its workers used the parent of the generated .codex directory as CODEX_HOME, so the generated integration was not loaded. The attempt was aborted, both temporary auth files were removed, the processes exited, and the seeded database was unchanged. V2 binds CODEX_HOME, config validation, native-session reads, and auth cleanup to generated.config_path.parent.

Original executed helpers and failure reports are preserved. The selected successful report retains synthetic messages and source line/file hashes, while reducing session metadata to identity and version fields. Full sessions, base instructions, credentials, runtime tokens, and databases are not archived. The original local report hash is recorded separately.

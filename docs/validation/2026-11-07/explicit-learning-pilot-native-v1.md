# Optional learning pilot: native validation attempt

The first native attempt failed validation during forgetting. Seven phases
passed before that failure. Original-source replay and recall after deletion
were not run. The optional pilot remains inactive, with zero actual use days.

The user authorized validation of the prepared four-file proposal, without
authorizing activation. Two disposable Git projects received the proposed
configuration and exact guidance bytes. Only launcher/storage paths and scope
registry identities were relocated. The native config reader loaded both
project-local server definitions and their twelve-tool filters. Neither user
config nor CLI flags supplied a replacement server definition or tool filter.

The run used the frozen `f5a944ea` wheel, Python 3.12.11, pinned Codex
`0.164.0-alpha.11.1`, `gpt-6-astra` with high reasoning, local BGE embeddings and
a 180-second limit per fresh session. Hooks and other host features were
disabled for isolation. The service retained its default internal maintenance
scheduler; no scheduled host memory requests were added. Extraction had no LLM
provider, and experimental modules remained disabled.

| Check | Result |
| --- | --- |
| Ordinary request in each project | Both passed; zero tool calls and unchanged memory state |
| Remember and inspect source | Passed; original durable job completed |
| Recall after service restart | Passed; same scoped fact and version |
| Second-project recall | Passed; its own fact and source returned |
| Correct and inspect source | Passed; same fact ID, expected version, original job completed |
| Recall correction after restart | Passed; corrected version returned |
| Reviewed forgetting | Failed the frozen trace checker |
| Source replay and recall after deletion | Not run |

The five accepted explicit phases contain 18 correlated Mnemos calls and five
complete native inventories. All eight executed sessions received the proposed
guidance. There were no phase retries or corrective prompts.

The failure audit reproduced `Native MCP dispatch correlation is incomplete`.
The forgetting session called the built-in `list_mcp_resources` and
`list_mcp_resource_templates` helpers before its seven Mnemos calls. Those two
helpers have no MCP dispatch correlation records, while all seven Mnemos calls
do. The checker compares correlations against every tool dispatch, including
the two built-ins. Its message does not distinguish those cases.

The supplemental audit also found a second rejection condition: a follow-up
inspection of the just-deleted fact returned a degraded result containing
`404 (fact_not_found)`. The checker rejects degraded results. This response
cannot be silently discarded or converted into a successful tool result.

Read-only diagnosis confirms the exact twelve-tool inventory, unchanged
reviewed deletion preconditions, the target's absence and preservation of all
three controls. SQLite integrity and foreign-key checks pass. These observations
do not replace the failed acceptance result or establish replay suppression.
The first diagnostic script also stopped on the degraded inspection result;
that script and error are retained alongside the completed failure audit.

Cleanup passed. All twelve recorded process identities were absent, copied
credentials and the disposable runtime descriptor were removed, and normal
credentials stayed unchanged. All 96 installed package files, 57 dependency
versions, 17 embedding assets and 14 watched live paths remained unchanged.
The original inactive installation still has no database or runtime directory.

The [receipt](explicit-learning-pilot-native-v1-receipt.json) binds the private
archive, raw traces, frozen runner/prompts, diagnostic scripts and results.
Raw project guidance and evidence remain private. The original quality, timing,
full-configuration and two-week pilot requirements remain open.

The next validation change should separate native call correlation from
operation outcomes, represent built-in discovery explicitly, and specify how
an expected missing-fact response is checked after deletion. That needs a new
prospective contract and deterministic checks before any further native attempt.
This attempt remains failed; activation is not ready for approval.

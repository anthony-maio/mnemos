# Retrieval strategy comparison protocol v1

This experiment compares four retrieval strategies against the same accepted SQLite snapshot for each held-out query: `vector`, `lexical`, `hybrid`, and `full`. The ordinary full source pipeline runs once per session and repetition. Each query then forks that accepted state into isolated strategy databases, so access metadata and later writes cannot cross strategy boundaries.

The run reuses the v3 held-out labels, 200 sessions, three repetitions, top-k 5, a 1200-token context budget, and the existing source and scope fixtures. The strategy candidate pool is `min(max(k*6, 20), max_candidates)`. Vector retrieval applies the cosine relevance floor 0.2. Lexical retrieval uses BM25 without embeddings or a semantic floor. Hybrid uses the current vector and lexical union/ranking. Full uses the production profile and modules.

The primary report is the per-query `quality_hit` comparison, reported separately for answerable, no-answer, semantic state-pair, and state state-pair labels. Missing, partial, incomplete, or unverified-provenance strategy rows are excluded from hit proportions and paired differences and are counted explicitly. Differences to full are paired within `(session, repetition, query, quality kind)` and clustered by session. Strategy order is deterministically shuffled from the session, repetition, and query identity. Latencies are retained as descriptive stage measurements only, including fresh-clone setup where available; this protocol does not claim a latency confidence interval or a 500 ms gate result. It makes no claim about equal CPU cost, human utility, or fresh data collection.

Preparation is offline and writes a bound `NOT RUN` manifest. Real execution requires an explicit model, `--think false`, and the exact protocol, dataset, strategy configuration, source provenance, and options binding. Resume validates those bindings and the recorded output/work paths before writing.

Each quality kind gets its own Wilson proportion interval and paired treatment-minus-full bootstrap interval, with session clusters. Expected query identities come from the dataset and repetition count, including absent sessions. Duplicate or unknown identities are rejected. Completed coverage requires every expected strategy result and verified model and embedding provenance. It is separate from passing any quality threshold or human acceptance gate.

`--resume` verifies and reads a completed comparison, including the report, embedded rows, raw JSONL, and summary hashes. It refuses prepared, failed, or incomplete runs without overwriting their artifacts. A new execution uses new output and work directories; it does not replace failed observations. Individual source databases are retained under the held-out attempt directory, while temporary strategy clones are removed after recording results. Timings for query dispatch and snapshot setup are separate; provider trace ranges identify calls attributable to each strategy.

# Local support learning after computational admission

Status: proposed data and learning design. No training is authorized by this
document. Bounded independent review permits synthetic data preparation; its
full-claim, critical-counting and overflow-coverage corrections are included.
The [capacity result](../validation/2026-11-11/cooperative-support-capacity-v1.md)
admits one explicit runtime configuration for computation only. The next
executable increment is new grouped development data and independent label
review. Resolve that gate before implementing or running a training attempt.

## Preserve the local and optional hosted paths

Local retrieval and evidence inspection must operate without a hosted key.
Develop the support classifier locally, using the same full 22-layer encoder,
trusted marker positions, shared per-target binary head and full owned sources
as the admitted computation. Use the explicit one-thread embedding setting
only in this candidate. Product defaults and live installations stay unchanged.
Jev remains an explicitly selected alternative. Never use its key, responses
or network access as an automatic fallback or a source of gold labels here.

The six measured workloads cover zero through five facts, up to eight retained
sources per fact, and complete framing within both 8,192 tokens and 64,000
payload bytes. They do not establish capacity for every combination within
those limits. This candidate must reject larger source inventories explicitly,
even when the existing serializer admits them. Unavailability counts against
coverage and answerable recall. Do not silently drop sources or facts.

## Build data that can expose the previous failure

Keep the old 127-case corpus, inspected partitions and failed model outputs as
known diagnostic material. Do not recycle them into new reserved partitions,
derive labels from predictions, or count renamed entities as independent data.
Use synthetic project material; no private project memories or credentials are
needed. Keep sources, requests and labels in separate bound records.

Author independent scenarios before writing paraphrases or counterfactuals.
Reserve entire connected scenario/source/template/variant families for train,
tuning or development. Shared reasoning categories are necessary; shared
construction templates across partitions are leakage. Do not generate all
partitions from one fill-in-the-blanks template. The existing normalized-content
and lineage audit is necessary, but a reviewer must also check undeclared
semantic and template ancestry.

For every partition, inspect supported counterparts and meaningful unsupported
contrasts for subject/relation, negation, missing and false prerequisites,
explicit hypotheticals, attribution versus observation, time and revision,
unresolved conflict, source ownership and injected instructions. Include
multi-target cohorts, a genuinely empty cohort and reordered candidates.
Include answerable cases beyond each source/token/byte bound and keep their
rejections in coverage and answerable-recall denominators.
Keep each contrast and permutation in its original connected family. Report
independent family counts, target balance and category coverage, including gaps;
more rows alone do not establish sufficiency.

A positive target must answer the query, and its own evidence must support
every material clause and qualifier under the requested time and circumstances.
A supported fragment cannot justify the complete candidate. A justified negative answer can be
supported. Missing conditions stay unknown; a rule is not proof an event
occurred. Critical positives require an explicit source-backed action
constraint. Bind critical flags to fact content and owned sources independently
of query relevance. Report unique critical facts separately from supported
opportunities; duplicates and permutations are not independent facts. Record
a source-specific rationale and audit critical flags.
Independent review must resolve every disputed or ambiguous label before
freezing the data. Neither mechanical checks nor a review-status field certify
semantic correctness. Sparse or one-sided categories block the data gate.

## Freeze one learning attempt only after the data gate

Use full-backbone supervised adaptation with the shared binary head as the
proposed learning design. This changes the backbone from the failed causal
candidate; the current capacity head is random and has never been trained.
Do not reuse its computation result as evidence that backward computation,
optimizer memory or the trained deployment artifact works.

After the actual corpus is reviewed, freeze a numerical recipe covering
optimizer and parameter groups, precision/master weights, gradient scaling,
loss normalization and class balance, sampling and accumulation, learning-rate
schedule, seed, step/time limits, checkpoint selection and decision threshold.
Show each target's effective contribution using the frozen class counts.
Keep labels and critical flags outside inference input. Authorize no sweep or
threshold rescue. Until these values are fixed and reviewed, training remains
blocked by preparation, not authorized by an unspecified recipe.

Before that attempt, prospectively bind one bounded backward/memory probe with
the real full-length input, exact model and proposed optimizer. A failure ends
the proposed training configuration. Keep infrastructure failures and repairs
visible; shortening the bound, changing depth or discarding evidence requires
a new design decision. Do not run another unchanged inference capacity screen.

## Decide whether to continue from the actual result

Compare the trained artifact with the unchanged backbone on the same frozen
grouped development inputs. Report precision, answerable recall, critical
retention, no-answer abstention, incompatible selections, permutation changes,
unavailable cases and errors by category. Known development results remain
development evidence. Preserve a failed attempt without another model, seed,
dataset or threshold search under this plan.

A passing development result still requires artifact/source parity and complete
retrieval-plus-support timing on the trained deployment artifact at 10,000
accepted facts. The original gates remain precision and critical retention
95%, answerable recall and abstention 90%, and warm complete recall p95 500 ms.
The separate 100 ms capture failure remains open. Independent fresh acceptance
must retain the original sample sizes, repetitions and uncertainty reporting;
new development examples cannot supply it. Native configuration, the original
two-week daily-use pilot and release delivery also remain separate obligations.

This increment prepares only the data gate. Do not repeat closed package/native
matrices, alter live pilot files, publish, merge PR #9 or start a hosted call.

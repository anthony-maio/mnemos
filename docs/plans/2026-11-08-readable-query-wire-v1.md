# Explicit query judgment candidate

The frozen packed probe failed relation matching, condition handling and order consistency despite intact inputs. A separate development candidate, `benchmarks/local_memory/readable_query_wire.py`, exposes the two judgments as named fields and full labels instead of paired letter codes. Its response includes temporal intent, a date when required, and an object keyed by every request-local claim label.

Each claim requires `relation` (`matches`, `excluded`, `unresolved`) and `conditions` (`applies`, `excluded`, `unresolved`). The instructions distinguish topic overlap from the requested relation and explicitly separate condition applicability from relation matching. Complete source text and annotations remain visible. The candidate does not omit competitors, select answers, reinterpret unsupported evidence as supported, or repair source annotations.

The decoder rejects missing or foreign claims, unknown values, extra fields, duplicate JSON keys and oversized replies. It translates accepted judgments into the existing evidence evaluator, which retains request binding, date validation, live source fences, conflict handling and unavailable states. Original readable replies remain in results. Reply-object key order cannot change claim association.

All 137 selected codec and decision tests passed in 3.89 seconds. The new parity check enumerates all 243 two-claim relation/condition/temporal combinations and compares decisions and selected support bases with the existing evaluator. Other cases cover full input visibility, reordered reply keys, malformed fields, duplicate keys, cross-request responses, incomplete transport and source revocation. JUnit is retained at `.venv/readable-wire-v1.xml`. Black formatted the two new files, and the diff check passed.

This is a model-free boundary implementation. No semantic, tokenizer, latency or production claim follows from decoder parity. Longer labels and field names may exceed the query-time budget. Before inference, prepare a distinct development cohort and freeze its requests, expected claim judgments, temporal intent, order pairs and execution limits separately. The execution owner must retain full requests and replies, verify actual tokenizer and model identities, and report supplied source annotations separately from extraction. Do not rerun or adjust the closed packed probe. Final acceptance still requires fresh cases, complete retrieval cost and all original quality gates.

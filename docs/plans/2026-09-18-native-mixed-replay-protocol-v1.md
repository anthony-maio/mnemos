# Mixed native replay protocol

This probe addresses T17 concurrent sessions and durable retry. It uses disposable Codex and Claude Code homes, synthetic messages, unchanged generated hooks, normal native trust/permission flows, an installed wheel verified against its build, and a clean Claude plugin snapshot. It never edits live profiles or submits the fixture to Ollama. Optional modules are disabled, vectors are lexical fixtures, and cognition is unavailable; this is an integration observation, not a memory-quality benchmark.

Both hosts complete an outage turn while malformed fixture configuration prevents service startup. The database must retain only its seeded project and foreign-project controls, and the shared outbox must contain both native user and assistant messages, including any provisional Claude capture. The coordinator then explicitly restores the fixture owner and releases two fresh native recovery processes together. Native hooks must replay the queue without a harness replay call.

The service test shim attributes each eligible queued capture to its native host process through Windows TCP ownership and process ancestry. It pairs only the same stable source event ID, delivered by distinct expected native PIDs belonging to Codex and Claude Code. Payload host metadata identifies the source conversation; the replaying host is independently identified from process ancestry. Provisional source records are excluded from pairing and checked separately for non-extraction.

Each request retains the existing two-second rendezvous deadline measured from service-submit entry, including attribution time. Waiters expire atomically and cannot satisfy a later pair. An event contributes at most one accepted pair. Later active requests may pair after an earlier request expires; the expired request remains a timeout in the report. There are no calibrated launch delays or deadline increases. This fixes the prior harness's stale first-arrival bookkeeping. The prior v3 failure remains unchanged and is not promoted by this protocol.

Acceptance requires all four native turns to exit zero with exact synthetic responses; positive recovery-process overlap; at least one same-event pair active within both two-second deadlines; positive measured request overlap; and both pair members committed to the same durable event and job. All queued events must map to one durable source event and job, the outbox must empty, and every normal native message must have one completed extraction job and one scoped fact-evidence link. Native transcript UUIDs and Codex turn identities must match the actual host records. Provisional Claude captures must remain deferred with completed capture-only jobs, identity-pending results, and no fact evidence. Both scope controls must survive. Complete-row hashes of facts, events, evidence, and jobs must remain unchanged after maintenance, service close, and a fresh owner restart.

Timeouts, hook/MCP diagnostics, and failed attempts remain visible. A passing paired observation does not establish that every replay request overlapped, that startup met a latency target, or that natural concurrency occurs at a particular frequency. Complete-host, Desktop, Hermes, configured-provider, real-model utility, and pilot acceptance remain separate. The final artifact preserves helper/protocol hashes and selected synthetic records, omitting credentials, runtime tokens, inherited instructions, and full native transcripts.

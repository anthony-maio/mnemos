# Live support composition on the known development questions

Run the implemented QA-v2/contrast-v5 intersection on all 44 original support
questions in three new repetitions. These questions have already informed
development. This experiment measures live composition, stability and cost;
it is not fresh quality acceptance. Preserve the earlier failures and scores.

Use the verified unlabelled input file with SHA-256
`87af4a70b776e56eedcb8ae9a5cb56244ddcddae2da3403e98fb2db4cce9b195`.
Keep literal questions, reference dates, baseline order, fact versions, scopes,
assertion status and retained excerpts. Reconstruct 44 disposable fact/evidence
views, with no extraction, retrieval, embeddings, source events or jobs. These
views do not reproduce original lifecycle execution or complete metadata.
Each repetition shuffles all 44 keys using Python Random with seed 2026110703;
freeze the resulting 132-entry schedule before starting either model.

Both selectors receive the full eligible cohort. QA runs every retained source;
its decisions do not filter the contrast input. Keep complete facts whose IDs
both components select, in baseline order. Preserve current-store fences and
the shared 30-second ceiling, including the contrast operation's 15-second
ceiling. Failure and timeout remain unavailable, never successful abstention.
Keep the original 90% recall/abstention and 500 ms recall requirements.

QA uses local `deepset/deberta-v3-base-squad2` revision
`eea39c60cc305c2e4a9504f5ff117294bebb42db`, verified asset hashes, CPU float32,
evaluation/inference mode, four threads, one interop thread and deterministic
algorithms with seed 2026110702. Pin Torch 2.10.0+cpu, Transformers 4.57.6,
Safetensors 0.8.0, Tokenizers 0.22.2, SentencePiece 0.2.1 and NumPy 2.5.4.
The isolated worker rejects more than 64 question tokens or 512 total tokens
without truncation. Keep the existing source-region decoder, boundary whitespace
clipping, strict positive margin over CLS, 30-answer-token limit and literal
span-in-fact requirement. Record all input IDs, masks, offsets and raw logits.

Contrast uses the original local Qwen3:14b Q4_K_M digest
`bdbd181c33f2ed1b31c972991882db3cf4d192569092138a7d29e973cd9debe8`,
Ollama 0.40.9, 8192 context, one parallel request and one loaded model. Preserve
temperature zero, thinking disabled, 1024 output tokens, the original all-candidate
contrast-v5 questions, complete distributions, 0.8 support threshold and 5120-byte
rendered prompt ceiling. Verify each typed request equals its original saved
request before inference. Record rendered prompts, schemas, provider responses
and every HTTP attempt. The existing provider retry policy remains in place
inside the same operation deadline; do not retry observations or hide attempts.

Bind source, harness, protocol, dependencies, input files and local model assets
before startup. Keep labels outside the selection driver. No downloads or cloud
fallback are allowed. Use a private model server and a separately owned QA worker;
verify the Windows interpreter behind its virtual-environment launcher. A cancelled
worker becomes unusable and is stopped. If its transport is tainted, abort the
remaining schedule and report those observations as not attempted. Keep every
started observation, including errors and timeouts.

Before the live run, verify worker tokenization against the 78 original eligible
source inputs, reject oversized inputs without inference, and exercise cancellation
with a delayed fake worker. Load Qwen using an empty prompt and make one unrelated
QA warmup; preserve these separately. Time each support observation from the
composition call through its final current-store check and returned selection.
This includes snapshot construction, QA IPC/inference/decoding, contrast prompt
construction/inference and fences, but excludes one-time loading, database seeding
and post-run grading. Record component, worker and provider times separately.
These are support-stage timings; no full-retrieval latency pass can follow.

Afterward, stop the owned worker, unload Qwen and stop the owned server. Verify
process cleanup, closed private port, unchanged file bindings and logically
unchanged databases. Independently reconstruct QA decisions, typed contrast
selections, intersections and scores from the raw records. Report all three
repetitions, changes from the known diagnostic and failures. Archive private
evidence and publish only aggregate results. This run does not activate the pilot,
change host settings or promote a production default.

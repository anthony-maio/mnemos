# Joint support computational preflight

The data-gate review permits this capacity-only run against corpus-v2's design. It does not permit training or semantic grading. Use synthetic requests only; the runner must not read corpus labels or assign supported decisions.

Freeze one configuration before loading weights: retained Qwen3-Reranker-0.6B revision `1f54aa72c421b677caa56ece526856f8c60144a5`, bare Qwen3Model plus the existing shared linear head, CUDA device 0 (RTX 4080), float16, SDPA, evaluation/inference mode, no KV cache, no optional hidden-state or attention output, no vocabulary head, batch size one, four CPU threads, TF32 disabled, seed 2026110807. Use the retained torch 2.10.0+cu128 / transformers 4.57.6 runtime without dependency changes. Reverify all twelve model-file hashes before loading and after measurement. Record the actual driver and device properties.

The prospective experimental admission bound is 4,096 tokens including all decision markers and 64,000 serialized payload bytes, with zero through five candidates. The token bound is chosen before measuring this candidate, not fitted to a passing clock. It is larger than the 552-token corpus maximum but does not assume runtime evidence is equally short. This is an experimental configuration limit, not a narrower product promise: oversized requests must fail in full as operational unavailability, count against coverage/recall later, and never be shortened to pass. No source truncation or source-selection change is permitted.

Prepare six synthetic shapes with the exact serializer and tokenizer: zero candidates; one short candidate; five short candidates; five candidates at exactly 4,096 tokens with one source each; five candidates at exactly 4,096 tokens with eight sources each; and five candidates at exactly 64,000 payload bytes using compressible source whitespace within the token bound. Source counts are workload examples, not a new admission cap. Preserve the serializer's source-inventory validation. Test rejection of a request exceeding the token bound and a request exceeding the byte bound before inference. Freeze requests, token/marker bindings, source and runner hashes in an artifact manifest. No inference may start if an exact-bound shape cannot be prepared.

For each shape run five unmeasured warmups, then fifty measured repetitions in a fixed interleaved shape order. Record every warmup and measured duration separately. The timed boundary starts before serialization/tokenization and ends after CPU materialization and finite/shape checks of all real-target logits, with CUDA synchronization. It includes batching, transfer and the backbone/head forward; it excludes initial model/tokenizer load, retrieval, transport and host launch. Record load time separately. The zero-target path must not invoke the backbone. Record observed forward counts and peak CUDA allocation/reservation.

The necessary computational screen is p95 below 500 ms for every measured shape, finite correctly bound output, no OOM or failed request, and unchanged artifact/model bindings. Passing means only that support computation is not already excluded by the complete 500 ms target. It does not reserve a demonstrated retrieval budget, establish complete-path latency, prove semantic quality, or show training-memory feasibility. Report the untrained head as a random computation, not a support judgment. No training gradients, optimizer or adapters are created.

Any operational error, OOM, invalid output or failed timing screen closes this configuration. Preserve failed samples and do not shorten the workload, switch dtype/attention, tune a threshold or rerun to seek a pass. The existing one-infrastructure-repair allowance does not authorize a semantic or timing sweep. Observe any running process through its existing handle; an observation timeout is not permission to restart.

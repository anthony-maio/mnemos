# Inference-only grouped-attention representation candidate

The failed 876.17 ms configuration remains closed. A new implementation candidate is justified by a concrete dispatch mismatch, not by a lower token budget, changed precision or backend sweep. On the pinned Windows runtime, FlashAttention is not compiled. Transformers omits the all-ones mask and enables native GQA; metadata dispatch for the actual 16-query/8-key-value head layout selects MATH. Repeating K/V heads exactly instead selects EFFICIENT. This identifies a representation-dependent dispatch path, not the complete causal breakdown of the old run's latency.

The candidate preserves attention values, sequence lengths, masks, causal behavior, scaling and dtype. It keeps native grouped heads when the runtime chooser identifies a fused implementation. Otherwise, inference expands K/V heads with repeat_interleave and calls the same SDPA operator. Missing or unknown private dispatch capability falls back to the explicit representation, not to a claim of fused execution. No backend is forced or globally disabled, no installed dependency is edited, and no source is dropped.

The adapter is opt-in under a distinct Transformers attention name and reuses the existing SDPA mask constructor. It initially supports full-attention prefill only; cached/decode and sliding-window requests are outside this experiment. The original SDPA registration remains unchanged. Any later run must record actual final dispatch inputs, including representation, head counts, layouts, masks, gradient mode, causal/dropout settings and the runtime's backend choice. The private chooser is version-bound and requires compatibility review on a runtime change.

An initial parity candidate failed CUDA FP16 backward tolerance at the actual head layout. That failure is retained and the tolerance is unchanged. The revised candidate keeps the native grouped operator whenever Q/K/V gradients are required, so the representation optimization is inference-only. Training-time speed, memory and semantics are not established by this choice. Any eventual training recipe must separately bind training and deployment paths and their numerical checks.

The numerical gate uses CPU float64 atol/rtol 1e-10 and CUDA float16 atol/rtol 2e-3 against the native math reference, with nonidentical heads and nonuniform upstream gradients. Cover the actual 16/8 head layout with 128-dimensional heads, causal and unmasked attention, boolean and additive padding masks, native grouped Q/K/V gradients, repeated-head inference outputs, and tiny-Qwen masked/unmasked integration. The repeated-head backward remains rejected; learned attention masks are outside scope and fail explicitly. No model quality or speed claim follows from those tests.

After code review and numerical validation, a new frozen capacity protocol may test this implementation once. It must retain the original six request/frame bindings, 4,096-token and 64,000-byte limits, dtype, device, warmup/repetition schedule and complete support-stage timing boundary. Include a bounded untimed retained-model numerical comparison before timing; do not reinterpret it as a rerun of the old timing result. Predeclare its tolerance and stopping rule. Any numerical, operational or timing failure closes the new candidate. No corpus labels, semantic grading or training may be introduced by this computational step. The complete 500 ms retrieval goal and all other original obligations remain unchanged.
